# 内存与重开体验开发规范

TabDo 设置、演示编辑器与呼叫AI是独立窗口，最小化或隐藏后仍计入活动会话。呼叫AI的聊天、模型调用、命令树和 context-mode 索引归当前窗口，关闭窗口即回收会话资源，保留结果产物和已安装能力。详见[呼叫AI](call-ai.md)。

本规范适用于宿主、设置、内置子组件和第三方插件。生命周期接口沿用 [工具规范](tools-development.md#生命周期与资源归属) 与 [插件规范](plugin-development.md#会话与前台资源)，测量事实见 [性能审查](performance-audit.md)。内存优化必须同时验收真实资源释放、任务安全和重新打开速度。

## 闲置目标与口径

100MB 是全应用完全闲置时的优化目标，不限制录屏、编辑、推理、媒体处理或用户主动保留的会话在活动期间的实际需求。进入该场景必须同时满足：

- 所有应用窗口均已隐藏或最小化，只剩隐藏的宿主页面；不存在可见辅助窗口或其他工具、设置、插件及 Provider 页面。
- 保存、导出、文件事务、请求、启动准备和清理链已经结束。原生截图、取色与捕获进程以 `close` 为结束边界，不能以窗口消失或发出停止请求代替。
- 没有用户开启的临时常驻会话。隐藏或最小化的常驻会话仍算活动，不纳入100MB闲置验收，也不能为达到预算而关闭它。

MB 按1,000,000字节统计。报告必须同时列出所有所属 Electron 进程的工作集和私有提交量，分开标记是否达到100MB；尚存的原生任务进程另列，不能漏算后宣称闲置。用户自行打开的浏览器、编辑器和终端不计入所属进程。

自动回归分别输出工作集与私有提交的100MB目标结果，未达标时保留分进程数值和待优化项，不在首次超出目标时中断后续测量。资源与会话退出、必要任务保护、数据恢复及下述重开时延继续硬性断言；测试流程通过不代表两项内存目标均已达成。

工作集表示当时驻留的物理内存，私有提交量表示仍保留的专用提交分配。两者不能互相代替。只有工作集达标时，必须明确标注私有提交量未达标；不将一次工作集下降描述为所有分配都已释放。私有提交量超过目标时，继续按主进程、GPU、页面和服务定位，并记录干净闲置基线、重复开关后的增量与尚未解决项。

## 优先释放真实资源

1. 创建资源后立即登记所属会话或任务的幂等清理器。退出先取消前台活动，再等待必要任务完成、失败、取消或超时，随后解除引用并销毁所属页面或进程。
2. 图片、视频帧、画布、模型、张量、解码器、Worker、对象URL、临时网络缓冲、事件闭包和启动输入都必须有释放边界。完成的释放器也应移出登记表，避免清理器本身继续持有大对象。
3. 不缓存已经退出的工具视图、模型或工作进程。可以保留有界的不可变指令索引和不携带会话状态的轻量资源，避免重复扫描与解析；大图、项目模型和推理资源按需加载。
4. 已持久化的历史和“上次匹配”可以在闲置时解除内存副本，用户恢复时再读取。保存失败的唯一副本必须保留，不能先清空再尝试保存；启动仍在准备时不能清除输入。
5. 日志只记录身份、状态、大小及耗时，避免序列化整张图片、完整启动输入或大段匹配正文，造成额外分配与长期落盘。

清理范围只包含所属运行时。保留配置、项目、原始文件、剪贴板历史、收藏、已安装插件与备份；全局剪贴板采集、托盘和快捷键服务继续运行。新增独立任务必须接入活动判定，不能绕开闲置门槛。

## 空闲调度与工作集辅助回收

全部条件满足后等待连续10秒再执行宿主闲置清理。任何窗口恢复、页面创建或任务开始都取消等待；必要任务和临时常驻保护优先于内存目标。仅失焦仍可见不算退出。

先解除无用引用，再判断预算。Windows 全应用工作集已经低于100MB时，跳过 `EmptyWorkingSet`，保留热页以减少重开调入。超出时仅在这次稳定闲置边界执行一次冷工作集归还，不设置长期内存上限，不按固定周期反复压缩。

辅助进程就绪后再次检查活动，并重新取得当前所属PID及创建时间；通过同一个进程句柄核对身份，防止PID复用。辅助进程最多15秒，完成、失败或取消后退出并解除全部引用。系统策略阻止时保留正常功能并如实记录失败。

不以强制GC轮询、终止共享GPU服务、关闭硬件加速、反复重启宿主或中断用户任务来追求数值下降。冷工作集归还只是物理驻留的辅助措施，不能作为私有提交量释放的证据。

## 联合验收

窗口流程使用隔离数据的源码 Electron E2E，不为测试构建安装包。源码 TypeScript 转译和 Vite 首次模块编译与生产版开销分开说明，不能把源码启动到闲置的自然下降算作优化收益。

同一实例至少分别记录首次冷开、热重开、闲置回收后重开。设置的热重开与回收后重开各采集至少3次，从真实宿主入口计时至可交互正文稳定，报告中位数与全部样本；不能只等标题或侧栏。重开时继续验证实际数据、IPC和任务能力。

当前 `idle-memory` 源码回归中，设置回收后重开中位数须低于3000ms，且不超过“热重开中位数的2倍”和“热重开中位数加400ms”中的较大值。这是同机源码回归容差，不是对所有设备的产品时延承诺。首轮模块编译单列，重型工具另外记录控制条及编辑正文就绪时间；调整容差必须说明测量依据，不能因回归失败直接放宽。

内存报告至少包含：干净闲置、活动峰值、关闭后35秒、继续闲置至65秒和重新打开；附主进程堆、外部内存、分进程工作集/私有提交量、存活页面和窗口。连续开关应验证资源数量不增长，并检查真实大输入引用已经解除；指标仍高时记录来源与限制。

安全回归覆盖必要任务结束前禁止回收、临时常驻隐藏后保留、退出清理、保存失败保护、持久资料按需恢复及重新打开后的正常操作。归档进入 `.artifacts/runs/` 与 `test-results/playwright/`，结论与未验收项写入当轮维护记录。
