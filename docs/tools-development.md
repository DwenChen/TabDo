# 内置“工具”子组件开发必读

修改或新增 `internal-plugins/system` 子组件及其宿主能力前，必须先阅读本文。插件标识固定为 `system`；子组件共用插件入口，但临时资源必须属于各自的会话或任务。

## 统一界面规范

子组件以现有剪贴板、OCR 识别界面为视觉基准。复用外部插件的布局或交互时，必须转接本项目的字体、主题和间距，不能连同外部主题整套引入。

- **字体**：复用 `src/styles/variables.css` 的 `--font-family-ui` 与 `--tool-font`（系统字体，13px / 1.6）。按钮、输入框、下拉框、文件名、新名称与手动编辑框均继承同一字体；正文可按阅读需要使用 13–14px，辅助文字 11–12px，局部栏标题 13–14px、字重 500–600。文件名不是代码，不使用等宽字体；仅代码、公式源码等明确内容可以例外。不要引用未随程序提供的网络字体。
- **强调色**：统一使用 `--primary-color`、`--primary-hover`、`--bg-accent-light`，默认绿色（浅色 `#059669`、深色 `#34d399`），保留宿主向 `--plugin-primary-color` 注入用户主题色的能力。选中标签、勾选框、主要操作、焦点边框和链接使用同一套变量；不保留上游写死的蓝色选中态、蓝色阴影。错误、警告、文件类型等语义色不作为主题强调色替换。
- **表面和边框**：复用 `--bg-app`、`--bg-surface`、`--bg-hover`、`--text-primary/secondary/tertiary` 和 `--border-color`；兼容宿主材质、明暗模式，不能通过写死白色或深色背景掩盖主题问题。悬浮提示、弹窗使用随明暗切换的不透明 `--bg-elevated`，不得直接复用透明页面背景造成文字叠透；状态提示优先占据自己的布局空间。控件圆角以 6–8px 为主，内容分栏 8–10px；避免厚重描边和大面积装饰阴影。
- **紧凑布局**：外边距通常 12–14px，控件间距 6–8px，内容分组间距 10–14px，常规按钮高度约 30–34px；按功能自然高度收紧工具栏。子组件正文不重复显示宿主已有的工具大标题与介绍，不加入重复选择入口、大型装饰空态或无功能的固定留白。列表滚动区保留可阅读空间，操作栏和确认按钮保持可见。
- **图片与结果**：识别类工具优先采用左图、右结果的等宽双栏，等待、处理中和完成状态保持布局稳定；只有空间不足时才切为上下布局。图片在所属栏内尽量充分展示，使用 `object-fit: contain` 保持比例，不为填满而裁剪或拉伸。二维码窗口按宽度计算有界正文高度，尽量接近方正，不再用横向大容器包一个小缩略图。长结果在结果栏内滚动，不能撑大整个窗口。
- **窗口与交互**：首帧尺寸与真实正文匹配；高度测量不得依赖 `vh` 再反向调整同一窗口，避免循环增长。宽度变化时可重新测量，监听必须随会话释放。按钮应有可辨认的禁用态和键盘焦点，图标按钮提供名称；支持拖放和粘贴的入口给出简短提示。

界面改动使用源码 Electron E2E 验证实际正文和交互。截图直接捕获插件 WebContentsView 当前可见区域，等待结果、文件行等稳定正文后再截取。涉及主题时检查明暗模式；涉及分栏和窗口尺寸时检查空态、结果态、图片比例、横向溢出及窗口高度稳定，不能只看标题或截图文件是否生成。人工视觉验收和未覆盖的 DPI/显示器边界据实记录。

固定导航与滚动正文优先分区，没有叠放的页面区域继续继承宿主材质；整页切换先撤下旧内容，不能铺满固定实色来防止重叠。材质验证同时覆盖窗口聚焦和失焦，避免只在失焦时融合。

所有覆盖正文的菜单、对话框、吸顶表头和浮动确认栏都须使用不透明 `--bg-elevated`；独立便签、图片标记窗口中的菜单、提示和文字输入框同样不得透出底层文字。遮罩、选区、OCR 定位框、图像画布、窗口圆角及录屏点击效果可以按用途透明，不能为修复菜单而填实整个透明窗口。增加 z-index 或 backdrop-filter 不能代替底色；滚动与弹出状态须验证明暗主题，审查记录见 [覆盖层审查](interaction-surfaces.md)。

## 生命周期与资源归属

性能与预算见 [性能审查](performance-audit.md)。Session 公共 preload 必须幂等注册；切换退出通知需要携带切换身份；RPC/就绪等待在超时和销毁路径也必须撤销监听。前台媒体读取被替换时，先取消并等待旧进程结束再启动最新请求，不能只丢弃旧结果。

- 返回搜索、切换插件、隐藏或最小化宿主、刷新主界面，以及独立窗口关闭/隐藏/最小化，均视为当前工具会话退出。窗口只是失焦但仍可见（例如打开菜单、开发者工具）不视为退出。
- 宿主立即将旧工具视图移出缓存，调用 `window.toolsLifecycle.dispose()`，随后销毁旧 WebContents。再次进入创建全新会话；旧异步结果只能操作旧会话，不能按插件路径查找并关闭新会话。
- **同插件内的子组件切换也必须退役整页**：不能因为所有工具的插件路径相同，就复用上一个子组件的 WebContents 或仅依靠 Vue 的 key/unmount。占位和窗口显示前先撤销旧视图可见性、移出显示树与缓存，再创建新会话；只有同一文本指令的无操作重入可以保持当前会话。必要任务仍归旧身份完成后关闭旧页面，不得在等待期间重新显示旧内容。测试须直接从可见工具切换到另一个工具，核对旧视图可见性、显示树、缓存及销毁，不能只测试先隐藏再打开。
- 子组件必须使用预加载创建的 `window.toolsLifecycle` 登记资源。查询、监听、定时器、Vue effect、Worker、模型/推理会话、图像/张量、对象 URL、临时缓存与子进程都必须有明确清理器，创建后立即 `addCleanup()`；异步加载完成时也要登记，已退出会话会立即释放迟到资源。
- `dispose()` 首先发出 `signal.abort`，立即执行前台清理。异步读取在每次 `await` 后检查信号或请求版本，禁止回填旧界面、重新注册监听、抢焦点或重新弹窗。组件卸载必须停止 effect、解除订阅并释放大对象引用。
- 清理器必须幂等；单个释放失败不能阻断其他资源回收。异步清理应在五秒内完成，超时会记录错误。`delete require.cache` 或丢弃 JS 变量不能代替模型的 `dispose/release`、Worker 的 `terminate` 或进程退出。

## 必须完成的后台任务

已确认的保存、导出、复制/粘贴及必要计算可以继续，但必须在隐藏窗口或首次异步操作前，通过 `runTask()` 登记完整操作链。只读刷新、轮询、预加载和界面动画不属于必要任务，不得借此保活。

```js
// 必须包含全部后续读写，不能在 operation 外继续保存。
await window.toolsLifecycle.runTask(async (task) => {
  const runtime = await loadRuntime({ signal: task.signal })
  task.addCleanup(() => runtime.dispose())
  if (task.signal.aborted) return
  const result = await runtime.compute(input)
  await persistResult(result)
}, 120_000)
```

任务使用自己的作用域，只保留必需资源。前台退出不会中断已经登记的任务；成功、失败或超时都会立即清理任务资源，最后一项任务收束后销毁页面运行时。退出后拒绝新建任务。必须设置合理任务上限（默认一分钟、最长十分钟）；任务必须响应取消信号，不能通过悬空 Promise、无限重试或未追踪的定时器长期保活。串行保存应在排队时登记并捕获前一个队列 Promise，避免退出丢失排队写入或形成自等待。

## 原生能力与独立进程

Windows 截图和取色通过 `resources/tools-native-worker.cjs` 在独立 Electron Node 进程按次加载原生模块，确认、取消、异常或宿主退出后结束进程；宿主等待进程关闭后交付最终结果。截图预抓帧最多保留两秒，未使用时也退出进程。

新增模型或重型原生能力优先使用同类独立进程隔离。必须登记并终止自己创建的整个进程树、关闭 IPC、等待退出；禁止按进程名称批量杀进程。用户主动打开的浏览器、终端和其他外部应用不属于工具运行时，不能随工具退出被结束。系统公共服务不得随子组件关闭：例如剪贴板全局采集由宿主持有，界面释放后继续记录新复制内容，重进时读取持久化历史。

当前本地版交付 Windows；其他平台的原生实现仍须分别验证，不能假设 Windows 的进程回收逻辑自动覆盖其他平台。

用户主动创建的悬浮图片/便签是独立可见窗口，运行时归属于该窗口，允许在剪贴板页面退出后继续显示。仅转交纯内容与有限操作，不持有旧工具 WebContents 或 Vue 模型；关闭、隐藏、最小化后销毁；文字便签仅在窗口内编辑，不保存或恢复历史。剪贴板文字默认追加到最近聚焦的存活便签，初始化期间通过队列转交；仅独立便签指令、加号按钮和 Ctrl+N 显式新建。窗口使用透明无系统边框，复用来源和许可见 `resources/tools-floating-ui.md`。窗口 preload 只暴露受宿主 sender 验证的有限 IPC，不开放 Node 或导航。

重命名、扫码预览的 Worker 和 Everything 查询桥接也必须在子组件切换时结束，不能只等整个工具插件销毁；复杂正则不能在界面线程执行。已确认的文件事务通过必要任务完整登记，失败或取消必须先回滚；用户自己运行的 Everything 不是工具子进程，不得随工具退出结束。

## 必须验证的退出路径

运行相关单元测试和 `pnpm test:e2e`，E2E 直接加载 `scripts/preview-main.cjs` 源码并使用隔离数据目录，不为验证打包。至少覆盖：无任务退出后旧 WebContents 销毁；必要任务完成/失败/取消后的资源回收；任务未结束时重新进入不会被旧任务关闭；异步加载迟到不会复活界面；独立窗口隐藏、最小化和关闭；截图/取色进程确认或取消后退出；剪贴板界面关闭期间复制的新内容在重进后可见。

测试不得删除持久化历史、收藏、用户配置或已安装插件来代替运行时清理。同步免安装预览只更新程序资源，使用 `scripts/sync-portable-preview.cjs` 对原有 `data` 和 `legacy` 逐文件比对，保留回滚资源。未经用户明确指示，不 push、不触发云端构建、不发布 release。

## 后台退出与子进程清理的分工

工具默认嵌入主窗口，所有插件均不再显示退出保活与跟随启动配置；第三方遵循 [新插件规范](plugin-development.md)。工具不再加入通用 `out-kill-plugin` 默认列表，仍保留专属的会话退出机制。

子组件清理负责取消请求、终止 Worker/查询桥接并释放图像、监听等资源；宿主 `releaseToolsView` 负责等待 `toolsLifecycle.dispose()`（包括已登记的必要任务）结束后销毁旧 WebContents，回收页面 JS 堆。只停止子进程仍会留下页面、Vue 模型与监听，所以两层职责都需要。

当前宿主统一退役工具与第三方会话，不再读取旧退出保活设置；`ToolLifecycle.dispose()` 复用同一个退出 Promise，宿主以 WebContents 标识和 released 标志防止重复关闭，Everything 的 `stopSearch()` 复用 closing Promise。组件卸载与作用域清理可能多次触发释放入口，清理器必须保持幂等，不能再次启动已释放的资源。必要文件事务先收尾或回滚，再销毁旧页面；全局剪贴板采集和用户自己的 Everything 不属于工具会话。

## 文件分类与便签贴靠

本地搜索重新对照 `local-search-neo` 提交 `691870b5b45a209f34b3626b162efeb00f177601`，复用分类侧栏、设置抽屉、分栏拖动与排序底栏（`internal-plugins/system/src/components/finder/`）。宿主搜索框负责关键词输入；全部、文件夹、EXCEL、WORD、PPT、PDF、图片、视频、音频和压缩文件在空关键词时也立即查询。桥接 `enumerate:true` 明确表示列举文件，普通空请求继续仅探测连接；正则只修饰关键词，分类仍使用 Everything 原生筛选语法。类别、排列、分栏与预览首选项保存于内置工具自己的命名空间，不读取外部插件配置。

多选文本悬浮按可见列表顺序合并全部选中的文本，保留现有追加路由。便签全部关闭后重置编号与轮色；桌面仍有便签时继续递增。贴边色签和展开便签属于同一个仍可见窗口，仅改变客户区尺寸并保存完整纸张大小，不缓存旧工具页面或复制正文。宿主按实际鼠标和窗口坐标判断贴靠及悬停，向所属窗口发布状态；页面不通过伪造 hover IPC 触发贴靠，追加文字时展开目标便签。拖动释放后由宿主在尺寸稳定时立即收起为色签，不再要求指针离开便签；指针停在色签上不再自动展开，点击色签或把色签拖离边缘才解除贴靠，解除后需再次拖动才会重新贴边。收起状态下的色签可沿所属边缘自由拖动，位置由用户决定而不是宿主固定分配。贴靠与解除使用分帧缓出过渡，色签与正文淡入，避免尺寸跳变；贴靠开关只作用于本次运行的整组便签，关闭时解除已有贴靠并恢复完整纸张，不写入用户配置。便签选项还提供正文字号（12–32 像素），只影响当前窗口。便签标题栏与普通悬浮图片使用受控拖动，操作入口校验 sender、坐标与纸张尺寸；接近和越过工作区边缘均识别。图片悬浮窗口按原图比例锁定尺寸并禁用原生边缘缩放，拖动只保留原点，窗口始终跟随图片不再留出透明区域。共享观察器只在独立可见窗口存活时工作，最后一个窗口关闭后立即停止。图片悬浮与标记按 edit 意图区分，普通悬浮不响应绘图快捷键。

## 子组件入口页面与窗口尺寸

新增可见子组件必须同时登记 `public/plugin.json` 功能、`App.vue` 路由、宿主 `api/renderer/commands.ts` 的工具视图白名单及 `pluginManager.ts` 的首帧高度。只增加清单和 Vue 页面会被误分到纯系统指令。E2E 必须走真实 `window.tabdo.launch`，不能直接挂载组件跳过宿主。

只开独立窗口的子组件（便签、悬浮内容、图片标记）在 `plugin.json` 声明 `mainHide`，面板或全局快捷键启动时不唤出宿主窗口；转交完成后入口页面主动隐藏宿主窗口并按内容收紧高度，避免闪出大页面。二维码扫描等固定内容界面按实测正文高度请求 `setExpendHeight`，不再沿用默认高度留下大片空白。

纯系统指令（复制路径、复制名称、前往文件夹、取色等）同样声明 `mainHide`，从超级面板或快捷键触发时不闪出宿主窗口。复制类指令由宿主 `clipboardManager.writeTextEntry` 写入文本并立即按文本条目登记，避免采集器把这次写入误判成文件条目。解散文件夹在插件私有桥接里逐项移动并删除空目录，冲突策略为自动重命名、覆盖或跳过，失败先回滚，历史与撤销记录保存在内置工具自己的命名空间。

超级面板使用最初的 250×400 DIP 默认尺寸，宽度固定 250，高度按内容在 250–400 内调整，保持宽度不大于高度；不得把 `getBounds().width` 的 DPI 舍入值用于后续尺寸更新。指令列表只显示名称、不显示功能描述，翻译结果与窗口位置等实际内容仍可展示。匹配候选中上一次使用的指令排首位，其余按真实频次降序，同频次再比较最近时间；打开时先读取最新统计，不能依赖加权分数保证首位。固定宫格和用户自己排列的项目继续保持原有顺序。

批量重命名主按钮统一为“执行重命名”。规则和手动名称改变后，预览以有界并发检查名称、文件身份、父子混合和目标冲突，逐行提示并禁用有错误或仍在校验的计划；支持主动刷新以处理外部文件变化。点击执行后仍在同一必要任务中重新校验并直接完成事务，不弹第二个确认步骤。预览是提前提示，不能替代事务发布前的防护。禁用重复提交，失败先回滚，成功后保留本次撤销；不能跳过校验或覆盖冲突文件。

## 录屏与网页快开

录屏的布局和交互以用户提供的 2.1.0 插件为准，不能只凭功能名设计近似双栏。对照全屏大图、窗口图标列表、区域入口直接进入可调整选区并显式确认、3–9 秒中心倒计时、自动保存与停止定位的完整流程；设置须有原版效果预览和位置选择。保留统一系统字体、绿色与明暗主题以及独立圆角控制条。参考界面只在隔离渲染器中展示，不运行原插件 preload 或读取外部软件数据。

录屏移植来源和原生参数见 `resources/recorder/README.md`。入口只枚举来源与收集选项；完整启动链（区域选择、目标选择、倒计时和进程启动）必须先登记必要任务。启动后录制所有权转交独立可见控制条，不保留旧工具 WebContents。停止按钮、F10、控制条关闭/隐藏/最小化和宿主真正退出统一等待捕获进程封装退出、工作进程关闭，再发布视频并清理临时资源。取消启动需销毁所属选择窗口；异常保留可恢复的视频并告知路径。禁止按进程名称终止其他应用。

控制条采用透明窗口内的 12px 圆角矩形，四角实际透明，保留拖动和停止。控制条必须在首次显示前设置系统排除捕获，避免第一帧或拖动后进入视频。区域模式以显示器原点加选区得到全局 DIP 矩形，优先放在选区下方、上方或侧面，再尝试其他显示器；全屏无空位时仍依赖系统排除。验证必须实际解码录制视频，不能只检查窗口保护标志或位置；不同 Windows 版本、显示器和缩放仍需人工验收。

网页快开配置属于工具私有 `web-quick-open` 键。`文本搜索` 匹配文字，使用含 `{query}` 的 HTTP(S) 模板编码关键词，在默认浏览器打开；多个启用项使用独立、紧凑的二级选择菜单，点击、键盘选择、Esc 和外部失焦均有明确结果。菜单只接收网站名称和 ID，限定 sender，选择或取消立即销毁；不能依赖已隐藏宿主的原生菜单焦点。`以图搜图` 只上传本次用户选中的图片到所选 Bing / Google Lens，不缓存用户图片、不使用第三方图床。Bing 捕获并验证 HTTPS 结果地址；Lens 由默认浏览器通过一次性内存表单直接上传，不能把应用内上传会话的临时地址当作跨浏览器可用结果。表单仅监听随机回环端口和随机路径、仅领取一次，60 秒无人领取或取消/失败立即清理；禁止图片落盘和常驻上传服务。表单使用无同源权限的 CSP sandbox、nonce 脚本、无缓存/无来源策略，并限定 Google 上传及结果跳转。完整菜单/交接链登记为有界必要任务，结束后释放旧页面；交接后用户浏览器保持独立。启动迁移不得把两个固定指令当作旧 `web-search-{id}` 动态指令清理。识图协议验证必须在独立浏览器会话中看到合成图预览和真实结果，只有 HTTP 跳转不算识图成功；外网、账号或风控限制据实保留人工项。

## 宿主真正退出时的原生清理

`appMain` 的 `before-quit` 先区分托盘主动退出、自动化关闭及开发终止信号；被拦截为隐藏的退出请求不停止全局采集。真正退出时先关闭原生提供商桥接，再调用 `clipboardManager.stop()`，停止剪贴板和窗口监听、拒绝新回调、取消复制等待并等待已接收的记录落盘，随后才再次 `app.quit()` 进入窗口/数据库销毁。清理 Promise 复用，初始化迟到不得重新启动监听。禁止在 `app.quit()` 后立刻 `process.exit()` 跳过此流程。

Windows 原生监听持有消息线程，必须显式调用停止接口；独立进程已复现不停止监听时退出码 `0xc0000409`，先停止后退出码为 0。`native-shutdown` 专项同时断言实际进程退出码和隔离数据重启留存，不能以 Playwright 断言通过替代退出码检查。子组件释放仍不得调用宿主的 `clipboardManager.stop()`。

## 媒体批处理

图片/视频功能、来源、边界与依赖见 [媒体工具说明](media-tools.md)。沿用参考插件三栏，接入统一系统字体、绿色强调色和明暗主题；右侧文件队列与底部操作不能被参数区挤出窗口。元数据读取为可取消的前台操作，确认批次才登记必要任务。独立 worker 持有图像、编码器与所属 FFmpeg 进程，取消后等待进程树退出再删除自己的临时目录；不覆盖源文件及已有结果。原生依赖必须连同完整生产版本树物理展开并核验，不能仅在开发环境通过。

媒体输出默认使用各源文件同级目录，合并取队列首项目录，无路径的剪贴板图片回退下载目录。自定义目录仍独立保存；不得删除旧设置来改变默认值。输出卷的暂存目录由宿主登记准备 Promise，工作进程确认后才编码，退出和取消等待全部目录准备及清理。搜索设置中的搜索方式与安装指引分组，提供普通用户可理解的说明；不展示命名实例等连接细节，自动识别常用实例并只读兼容旧配置。

## 指令清单、分类与任务栏

以下规则适用于新增和修改的全部工具入口，属于持续开发约束。每轮须连同相邻功能盘点，清单及准确图标来源同步维护在 [工具指令与图标清单](tools-catalog.md)。

### 指令去重与中文命名

- **按实际功能判断重复**：不同指令名最终执行同一功能、没有不同操作或输入含义时，只保留最简单、最明确的一个中文普通指令。不得再用英文、翻译名、同义词、长短名称给同一功能增加普通指令条目，例如“录屏 / 屏幕录制 / 录屏助手 / Screen Recorder”只保留“录屏”。不要只做字符串去重而遗漏语义重复。
- 名称优先使用用户熟悉的中文动作或功能名；功能说明与匹配标签保持对应且不歧义。需要额外搜索能力时使用现有拼音/搜索机制，不恢复被清理的重复条目。用户自行设置的别名不作为内置重复指令清除。
- **保留有效输入与不同操作**：文本、图片、文件、窗口是不同匹配来源，即使标签相同也不能直接删除；必须保留原匹配范围、文件类型、数量和长度限制。区域录屏与停止录屏是不同操作，应保留各自功能并归类，不能因都属于录屏而删掉。
- 改名、归类和换图标不改变已有功能码，不批量重写、清空用户快捷键、固定项、别名或使用记录；确需迁移时另行设计兼容与数据保留验证。

### 功能归类

- 相关操作必须收拢到同一功能分类，例如“录屏”下包含录屏、区域录屏、停止录屏；图片处理、网页快开、文件操作等按同一原则整理。分类名称保持简单明确，不以新增平级卡片继续分散同类操作。
- 工具清单用 `group` 声明分类，设置“所有指令”的功能/匹配页和插件详情共用 `groupToolFeatures`，分类名参与搜索。保留每个成员的原始功能码和完整命令定义，禁止用分类名称代替启动、禁用、快捷键、固定或别名的身份。
- 归类仅整理工具展示，不合并不同操作的实现，也不改变第三方插件的指令结构。

### 图标设计与来源

- 不同功能必须使用与其内容对应、轮廓可区分的专属图标，不得大面积重复使用截图、文件夹、剪贴板等通用图标，也不能只换颜色来掩盖同一图形。**同一功能的不同匹配输入可共用该功能图标**；图标线条、尺寸、留白和同类配色保持一致。
- 优先搜索公开、免费且许可允许随软件分发的图标库；没有合适图形时可使用生图技能创制专门图标。采用外部资源须保留准确来源地址、版本或提交、完整许可、原始图形及功能映射；不能只写“来自网络”或仅保留网站链接。生图结果同样记录来源方式与后续加工。
- 运行时只使用随程序提供的本地资源，不依赖网络加载图标。当前采用 128×128 PNG，兼容指令列表、搜索、超级面板和原生窗口，原始 SVG 与来源清单一并保留；图形在小尺寸、明暗主题下都必须可辨认。
- 图标变更必须核对每个受影响功能的清单引用、实际页面和窗口入口，同步构建与免安装预览资源，不能仅替换源码图片后就声称已交付。

### 任务栏与验证

- 全面检查嵌入正文、手动分离、直接独立打开、便签、悬浮图片、图片标记、窗口信息及录屏控制条。每个可见工具窗口必须具备对应功能的原生图标和任务栏入口，不能依赖已退出的父页面或通用空图标。
- 可见正文使用 `applyToolsWindowIdentity`，退出搜索、隐藏、切换、终止或分离时撤回宿主工具任务栏身份；独立窗口须在首次显示前设置图标。临时选区、倒计时、输入效果与二级选择菜单属于所属任务的覆盖层，不单独占据任务栏。
- 新增子组件必须同步清单、宿主路由、首帧高度、窗口身份和 `tools-catalog` 实际正文检查；新增普通指令前复核整份清单的语义去重与分类，换图标时检查全部受影响入口。
- 使用源码 Electron E2E 验证分组后单条指令的操作身份与匹配规则，检查打开、退出、分离及资源销毁。图标专项同时核对实际传入原生窗口的对应图标像素、Windows 原生图标句柄和真实任务栏设置调用，不能只断言文件存在。截图等待稳定正文，直接捕获插件 WebContentsView；视觉、任务栏合并策略及多屏/DPI 未覆盖部分如实留作人工验收。
