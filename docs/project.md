# 项目定位与版本策略

## 产品定位

TabDo 是由 DwenChen 独立维护的 Windows 桌面工具箱。核心交互是鼠标驱动的超级面板：把文本、图片、文件及窗口上下文交给适合的本地工具或按需插件，减少常用操作的切换成本。

产品提供内置工具、悬浮中转、可配置的翻译与识别能力、独立插件市场及本机数据管理。工具和插件按需运行，用户可为支持的当前会话开启临时常驻。基础文件处理在本机执行，在线翻译、AI 和搜索由用户选择服务。正式交付平台为 Windows x64。

## 仓库与维护边界

主仓库为 [DwenChen/TabDo](https://github.com/DwenChen/TabDo)，插件市场为 [DwenChen/TabDo-plugins](https://github.com/DwenChen/TabDo-plugins)。主仓库负责宿主、内置插件和应用发行；市场仓库负责扩展插件源码、索引和发布包，二者分别管理版本。

TabDo 源自 [ZToolsCenter/ZTools](https://github.com/ZToolsCenter/ZTools)，保留必要 Git 历史、原作者版权和第三方来源记录。仓库按独立项目创建，不加入上游 fork 网络；这一托管关系不改变源码来源、许可义务或作者署名。上游致谢见 [README](../README.md#许可与致谢)及[来源清单](third-party.md)。

## 版本规则

独立仓库以 `1.0.0` 作为首个正式版本，后续采用 `MAJOR.MINOR.PATCH`：

- MAJOR：不兼容的公开接口、数据格式或操作方式变更。
- MINOR：保持兼容的新功能。
- PATCH：兼容性修复及小范围改进。

`package.json` 是应用版本的唯一来源，发行标签为 `v<版本>`。应用发行、内置插件清单和第三方插件各有职责，不为统一数字而改写插件自己的语义版本。发布后不覆盖同一仓库中的版本标签或同名产物。

重定位前的 fork 仓库曾发布 `1.x`、`2.x`；这些编号仅表示旧仓库的开发阶段。Git 历史、`docs/history/`、历史性能审查与生成索引保留当时版本及验证事实，不追溯改号。旧仓库的标签和发行包不迁入新发行序列，本地备份保留恢复依据。

## 兼容承诺

保留应用安装身份、默认数据根目录、数据库格式、内置插件标识、稳定功能码和已有配置。初始化仅补缺失配置；显式空列表、关闭状态和自定义选择同样属于用户设置。

旧 fork 仓库的 `2.x` 用户需手动更换为本仓库的正式版，步骤见 [发布与升级](release.md#从旧仓库版本迁移)。数据重置、在线数据库复制和批量重写插件命名空间不属于版本迁移。
