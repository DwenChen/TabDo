# 性能审查与资源预算（历史测量）

本文保留 2026-10-21 至 2026-10-22 的审查条件、测量结果与原始版本标识，末尾补充 2026-10-28 的闲时专项。当前测试结果以当轮维护记录为准。

该次审查覆盖宿主、超级面板、搜索索引、插件 Session、设置页路由、工具入口的 37 个功能码及其 10 个异步页面组件。保持现有功能、交互、布局、主题、指令名称和图标。依据当前源码检查资源归属、异步过期处理、缓存上限、请求并发与退出路径；下表明确区分该次审查改动、保留设计与实际测试范围。

## 测量方法与结果

`tests/e2e/performance-budget.spec.ts` 使用源码 Electron、同机隔离数据和临时旧数据目录。重复切换 6 次；真实调用匹配链；确认旧 WebContents 关闭、Session 注册数量稳定、1040 条历史分类缓存不保留正文；实际等待 30 秒验证闲置页面销毁。性能测试不强制 GC，不修改用户配置，不把工作集的单次变化当作普适收益。

最终同进程对照（`.artifacts/runs/2026-10-21T15-25-16-508Z-e2e`）：固定 600ms 系统复制延迟，仅替换系统输入边界，交替运行 3 次顺序创建与 3 次提前准备；正文可见耗时中位数由 **1923ms 降至 935ms（约 51%）**。这是控制复制延迟的源码对照；真实原生选区链由 super-panel-selection 单独验证，不能将此数字当作所有应用/设备的承诺。

同轮交替对照原有完整页面启动链与宿主直达链各 3 次，文本搜索二级菜单中位数从 **905ms 降至 395ms（约 56%）**，直达入口未创建工具 WebContents。直接冷开面板约 939ms，短期复用约 34–45ms，测量包含 Playwright 往返及正文断言。首次二维码涉及 Vite 首次模块处理，不能把开发服务器的冷编译耗时作为发布版进入时间。

30 秒闲置后 WebContents 回到仅宿主 1 个、工具缓存 0 个；该次 Electron 进程工作集总和约 434MiB，面板再次打开并隐藏后约 598MiB。工作集包含主进程、GPU、服务与页面，受 Windows 回收和开发服务影响；这是资源确已释放的辅助证据，不是独立 JS 堆或生产版常驻内存指标。

原始 JSON、主进程日志、截图与 trace 仅在 `.artifacts/runs/` 和 `test-results/playwright/`，不提交。最终执行结果及预览校验以该次审查历史记录为准。

## 保留边界

- 2026-10-21 轮次保留的第三方保活策略已由下方 2026-10-22 的 session-v1 策略替代。内置 provider 继续完整传递 AbortSignal。
- 不增加常驻工具页、常驻模型、启动预热进程或主动 GC 轮询。短期复用面板与 30 秒闲置回收是启动速度和闲时资源的明确折中。
- 文件历史全量分类/排序、合并媒体画布和用户主动打开的多个独立窗口仍随真实内容增长；输出尺寸、分页和任务数有界，但不承诺所有输入都获得相同峰值内存。
- 不改变用户配置、收藏、剪贴板历史、已安装插件或原始文件。不同 DPI/多屏、显卡/音频设备、真实 Everything 索引、外网与第三方插件内部性能继续以设备验收为准。

## 重定位前内存审查（历史版本 2.0，2026-10-22）

第三方插件与子组件使用一致的退出策略：所有前台页面在隐藏、最小化、切换、刷新后立即移出缓存，清理前台资源；只保留已登记且有时限的必要任务，完成、失败或超时后销毁旧 WebContents。随主程序预加载与退出保活设置已删除。可见独立子窗口持有自己的会话，父页退出解除引用；子窗口隐藏或最小化后也收束。

隐藏 Provider/动态指令调用采用引用计数和合并装载，最后一个调用结束释放隐藏页；Provider 调用登记为有限任务，旧页面退出不会误杀仍在完成的计算。资源登记支持主动提前释放并移除闭包，防止长时间可见页面积累已完成资源。独立市场并发查询共用一次索引请求，只在请求期间持有完整索引；最新版本缓存最多128项，索引网络缓冲最多2MiB/15秒，异常响应取消所属请求。

源码第三方压力回归（`.artifacts/runs/2026-10-21T16-19-24-640Z-e2e`）：连续8次创建并实际填充32MiB缓冲后隐藏，旧页面全部关闭且插件缓存归零。后台保存后重进、旧任务完成、超时清理，以及独立子窗口父页退出后继续可见/最小化回收均通过；最终 WebContents 回到仅宿主1个。工作集初始约589MiB、峰值740MiB、结束约543MiB。数值来自源码开发进程，未强制GC；资源数量是释放证据，工作集仅作同机辅助，不作为生产版内存承诺。后续增加并发Provider后重验结果见该次审查维护条目。

同轮原有性能专项：Session preload 连续6次保持1份，30秒闲置后仅宿主1页/工具缓存0。固定600ms复制延迟的交替对照中位数1912ms→923ms；文本菜单896ms→389ms。它们验证既有优化在更名和新策略后保持有效，不是该次审查相对上一版新增的速度收益。

迁移清理只涉及运行时资源，保留真实配置、私有数据、剪贴板与安装插件。默认数据根仅新安装使用 .tabdo；已有 .ztools 和位置指针原地兼容，旧备份格式继续可恢复。全量测试、最终预览及云端发布结果以该次审查历史条目为准。

## 演示录屏与日常闲置（2026-10-28）

`idle-memory` 回归使用同机源码 Electron、临时 data 与 legacy：关闭首次设置后记录基线，三次进入演示编辑器，其中一次实际录制；再依次打开并退出剪贴板、扫码与网页快开，等待 35 秒。报告分别记录 Browser、GPU、Utility、页面的工作集和私有内存，附存活页面和窗口。源码初启包含 TypeScript 转译与 Vite 编译开销，不能拿初启到闲置的自然下降宣称优化收益；原代码与修改后使用相同场景另作对照。

本轮发现与处理：

- Electron 会保留创建过的 Session。演示辅助窗口原先每次使用唯一分区，串行开关会积累原生缓存；现在只按并发需求独占租用，清空权限、连接和临时站点数据后复用，禁用 HTTP 缓存。单测验证 20 次串行打开只复用原分区，并发会话互不干扰，清理未完成或失败时不复用。
- 直接移除 iframe 不会替应用执行 React 组件卸载。编辑正文交给控制条前先卸载，退出时等最后一个必要任务结束再卸载，使视频、音频与 Pixi 的清理有明确边界；单测验证导出完成前不卸载，完成后先卸载再关后端。
- 隐藏宿主允许 Chromium 后台节流；退出清空子输入文本，可重建图标缓存在最后一次使用 30 秒后释放。全局剪贴板、用户配置、历史、收藏、插件和项目文件均不属于清理范围。

初轮资源验收确认退出后只剩宿主页面、工具缓存归零、捕获分区复用以及完整录制/导出可继续；当时未主动回收工作集，GPU 私有提交仍高于初启。该轮历史数值保留在 `idle-memory-and-guides` 记录。后续 Windows 闲时策略见下节。

## Windows 闲时常驻内存

当前内存开发和联合验收规则以 [内存与重开体验规范](memory-development.md) 为准；下方历史测量保留当轮条件与结果。

设置、演示录屏和其他子组件继续先执行所属生命周期清理，等待保存、导出等已登记必要任务结束。只有所有窗口不可见或最小化、全部工具/插件页面已销毁、原生截图与取色进程均已收到退出事件，媒体任务、快速录屏、演示运行时与内置提供商请求及事务均已收尾，且仅剩隐藏宿主时，才开始连续 10 秒闲置等待。隐藏的必要任务页、临时常驻会话和 Provider 页都会阻止回收；重新打开窗口、创建页面或启动原生工具会取消等待及尚未执行的辅助进程。

稳定闲置后先解除宿主启动参数和已持久化的匹配内存副本；上次匹配按需恢复，保存失败的唯一副本保留。Windows工作集已经低于100MB时保留热页，超出时才通过 [EmptyWorkingSet](https://learn.microsoft.com/en-us/windows/win32/api/psapi/nf-psapi-emptyworkingset) 一次性归还本应用冷工作集。不设长期工作集上限，不轮询压缩，不结束 GPU、音频、网络或宿主进程，不关闭硬件加速。辅助进程准备完成后重新判定闲置并读取 Electron 当前进程清单；打开每个进程句柄后再核对创建时间，防止旧 PID 被复用。辅助进程最多运行 15 秒，完成即退出并解除引用。系统策略或权限阻止时保留正常应用行为并记录未完成。

100MB 验证口径为全部 Electron 进程工作集之和（字节数小于 100,000,000），不是只统计主进程，也不是私有提交量或显存。冷页可能继续作为系统可回收页缓存存在，重新使用时会重新进入工作集，因此该策略不代表所有内存分配已经解除；报告同时保留 `privateBytes`。重新呼出可能出现页调入开销，活动期间不限制录屏、编辑、识别或媒体处理的真实内存需求。

`idle-memory` 专项分别覆盖设置反复开关、真实录屏与编辑器开关、剪贴板/扫码/网页快开退出、必要任务阻止回收、35 秒与 65 秒闲置，以及回收后重开设置并读写隔离资料。测量使用源码实例与隔离数据，不把源码转译开销计入生产版承诺；本机数值及其他设备未验收项据实记入 `idle-memory-budget`。

本机最终源码测量（MB = 1,000,000 字节，全部 Electron 进程求和）：

| 场景 | 常驻工作集 | 私有提交量 |
| --- | ---: | ---: |
| 设置三次开关后闲置 15 秒 | 24.605 MB | 537.043 MB |

三个阶段均仅剩宿主一页；必要任务保留时不会回收。此结果通过常驻工作集预算，**私有提交量未达到 100MB**，不能将两种口径混为全部内存均已释放。原始证据在本轮维护记录引用的自动归档中。

## 内存与重开体验联合验收

后续按 `memory-experience-policy` 执行真实引用释放与重开联合验证。发现宿主两处启动参数和上次匹配缓存没有闲置释放边界；现在在全部会话、启动准备和必要任务结束后清除临时输入，已保存匹配按需恢复，数据库写入失败保留唯一副本。指令索引继续复用，工作集已低于100MB时跳过冷页归还。

最终源码专项在必要任务等待时实际持有16MiB连续启动字符串，退出后35/65秒两处启动引用与匹配内存缓存均为零；保存记录可恢复。设置热重开三次中位数789ms，回收后748ms；演示控制条热重开约2.38–2.40秒，回收后约2.32秒，本机未见明显退化。首次控制条约11.18秒包含Vite模块冷编译，单列而不与热重开混比。
