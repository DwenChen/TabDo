# 版本发布与升级

本文规定 TabDo 的版本、构建、发布和成品验收流程。当前发行平台为 Windows x64；开发验证见 [开发指南](development.md)，日常交付及授权要求见 [维护流程](maintenance.md)。

## 发布前条件

当前用户明确授权本次 push、云端构建和 release 后，才执行远端操作。历史记录、脚本示例、Git hook 和已有发行版不延续授权。数据重置属于独立动作，不由发布授权推导。

发布候选需要完成：

**文档检查和必要更新必须在 push、云端构建、Release 前完成。** 对照当前源码审校受影响的 README、开发规范、两份本地教程、更新说明及当轮记录。即使无需改文档，也要确认仍然准确；通过 `pnpm docs:check` 与 `pnpm maintain:check` 后才能继续。推送 hook、构建作业和发布作业分别设有文档校验，不能跳过，也不能以一次历史通过覆盖后续改动。

1. 更新 `package.json`、`changelog.md` 及结构化维护记录，确认版本与标签一致。
2. 执行 `pnpm typecheck`（主进程与宿主页面）、`pnpm typecheck:setting`、完整单测、受影响的源码 Electron E2E 和相关静态检查。
3. 同步并核验本地免安装预览，逐文件确认配置、数据和已安装插件保留。
4. 执行 `pnpm maintain`、`pnpm maintain:check`、`pnpm docs:check` 与差异检查；确认暂存清单不包含本机资料、备份、日志、截图、安装包或凭据。
5. 通过 hooks 提交，检查远端 `main` 指向预期提交。

## 构建与发布

推荐推送候选提交后，在 GitHub Actions 手动运行 `Release TabDo` 工作流，选择 `main`。也可在明确授权下推送与应用版本一致的全新标签来触发；一次发布只采用一个入口，避免重复运行。

工作流由 GitHub 托管 Windows runner 安装根项目及设置插件依赖，先执行维护与文档校验，再运行类型检查、单元测试和 `pnpm build:win`。测试结果归档为 `verification`，Windows 制品归档为 `win-x64`。发布作业再次检查同一提交的文档，通过后创建版本标签并发布正式 Release。

发布流程使用仓库的 `GITHUB_TOKEN`，无需上游发布服务器或同步密钥。当前不配置 Windows 代码签名，也不发布 macOS 或 Linux 产物；这些平台的脚本存在不代表完成正式验收。

## 产物与验收

| 产物                                      | 用途               |
| ----------------------------------------- | ------------------ |
| `TabDo-<版本>-win-x64-setup.exe`          | Windows 安装程序   |
| `TabDo-<版本>-win-x64.zip`                | 完整免安装程序     |
| `TabDo-<版本>-win-x64-setup.exe.blockmap` | 安装更新差分元数据 |
| `latest.yml`                              | 标准更新清单       |

跟踪工作流直到构建与发布完成。核对运行提交 SHA、标签指向、Release 状态与版本，下载全部产物并校验 GitHub SHA-256；再核对 `latest.yml` 的版本、文件名、大小及 SHA-512。检查 ZIP 内的应用版本、程序资源与必要许可，并保留核验收据。只有触发成功不能记为发布完成。

构建失败时先根据日志定位原因，修复后重新验证。已发布版本不得覆盖或强推；需要修复产物时发布后续补丁版本。

## 从旧仓库版本迁移

本仓库从 `1.0.0` 开始独立计数。旧 fork 仓库的 `2.x` 版本不会把较小编号识别为自动升级，需要从本仓库手动下载当前正式版。两个仓库中相同的版本数字也不代表同一程序，应核对发行仓库与发布日期。

1. 在现有程序中导出完整备份，并退出全部所属进程。
2. 安装版运行新安装程序；如果安装程序阻止较小版本，先卸载旧程序并保留应用数据，再安装新版本。不要选择或手动执行数据清理。
3. 免安装版完整解压到新的程序目录，保留原资料位置和显式启动参数。免安装不表示默认使用程序目录保存数据；自定义隔离启动器仍应指向原资料。
4. 启动后检查设置、快捷键、固定项、剪贴板历史、收藏和已安装插件。需要恢复时按 [数据恢复流程](backup-and-migration.md#恢复与回滚)操作。

仓库内的手动测试始终通过 `PreviewPortable.cmd` 启动 `.local/portable-preview/`。同步脚本仅替换程序资源，不重置 `data`、`legacy` 或已安装插件。
