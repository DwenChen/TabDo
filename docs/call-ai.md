# 呼叫AI开发与使用规范

呼叫AI是 Windows x64 内置子组件，功能码为 `call-ai`。普通指令只打开一次性对话，不读取剪贴板。文本、图片和文件匹配带入所选资料，窗口匹配带入该窗口路径。剪贴板图片匹配会创建当前对话的临时文件，发送前可打开、悬停查看路径或移除。发送时附上文件路径，支持图片输入的模型还会收到图片内容。单张最多 4 MiB，关闭对话后自动清理临时文件。

输入框工具栏提供附件、引用、结果目录和发送图标。通过回形针图标可选本地文件，也可将文件和文件夹拖入窗口，每轮最多 12 个。文件匹配和拖放使用相同的附件处理。普通文件和文件夹提供路径供工具按需读取。声明支持图片输入的模型可直接接收 PNG、JPEG、WebP 和 GIF，单图最多 4 MiB，同轮最多 8 MiB。超出图片限制或模型不支持时仍提供路径。历史上下文仅保留最近一轮图片的字节。

## 框架与提供商

聊天模型请求使用 Electron 网络栈，沿用系统代理或 TabDo 通用设置中的自定义代理。发送时等待当前代理配置生效。

使用 [pi agent core](https://github.com/badlogic/pi-mono/tree/main/packages/agent) 1.5.0 的工具循环，构建时只打入实际使用的循环、参数校验和事件流，载荷约74KB；未使用的pi提供商不随程序打包。模型通过 TabDo 现有提供商适配器调用 OpenAI Chat、Responses 或 Anthropic。没有独立密钥表单、会话历史、跨对话记忆或进化功能。当前窗口中的多轮上下文只在内存中存在。

内置文件读写、代码执行、提问和能力管理工具。用户配置的 MCP 与 Skill 通过输入 `/` 按轮加载。聊天正文支持汉字紧贴书名号等开头标点的粗体，代码片段保留原有星号。

## 权限与退出

首次打开使用“请求批准”。确认过的权限模式保存在本机，新窗口恢复上次选择。启用“完全权限”须通过原生确认，输入框以红色盾牌提示该模式。获准代码和完全权限代码以当前用户身份访问文件与网络。

“请求批准”模式下，文件、代码执行、安装及 MCP 操作先展示完整参数。“批准本次操作”只批准当前操作。内联代码的审批卡片提供“允许类似命令”，在当前窗口内复用相同执行工具和完整参数的批准。代码、解释器、路径或其他参数改变时重新审批，关闭窗口即撤销这类批准。基本执行边界包括独立工作目录、最小环境、IPC 身份校验、路径链接防护、输出上限、超时及 Windows Job Object 进程所有权。

命令在挂起状态下先加入 Job 再恢复执行，不允许 breakaway，根命令结束、取消、超时、窗口关闭或宿主退出均回收所属后代。独立编译器由 Windows .NET Framework 提供，准备失败时拒绝执行，不降级为无进程所有权的执行方式。

- 每次模型请求连续 120 秒没有收到模型流事件才超时，收到正文、推理或工具调用事件会重新计时。
- 执行工具和等待批准、回答使用各自的计时。普通命令默认 120 秒。内置 Node.js 和 Python 的 `run_code` 可通过 `timeoutSeconds` 为本次脚本指定 1 至 900 秒，参数会列在审批卡片中。
- MCP 连接和工具发现分别限时 30 秒。MCP 工具默认等待 120 秒，服务端发送进度通知时重新计时，单次调用最多等待 900 秒。用户回应最多等待 5 分钟。

聊天在独立窗口中打开，隐藏、最小化或失焦时保留会话。关闭窗口即撤销本会话能力，中止模型、未回应请求、命令及 MCP，销毁内存聊天和临时目录。用户自行打开的外部程序、配置、已安装插件及宿主全局剪贴板不属于清理范围。

## 运行时与设置

聊天输入框工具栏集中模型、权限、附件和网页搜索。模型选择器收起时显示模型名，展开后显示提供商、完整模型名和已配置的说明。权限收起时以盾牌图标区分模式，展开显示文字。地球图标切换网页搜索，高亮表示已开启。

设置侧栏的“呼叫AI”提供独立的 Skill 和 MCP 管理列表，条目可展开并单独启停。展开 Skill 可查看 `SKILL.md` 声明的描述。展开已配置的 MCP 后，点击“查看工具”临时连接服务，显示工具名称和说明，完成后释放连接。全局规则和运行时默认折叠。在全局规则中逐条添加、编辑或删除，按列表顺序应用到每轮对话。旧版多行规则作为一条保留。手填路径在编辑结束后保存，目录选择和列表操作确认后立即生效。首次分离窗口为 650 × 440 的正文尺寸，缩放后的尺寸按呼叫AI单独保存。

Node 24 LTS 和 Python 3.13 嵌入版由 `pnpm build:call-ai` 从官方站点准备到忽略提交的 `resources/call-ai-runtime/win32-x64/`，随本地程序分发。运行时清单记录具体版本和来源。Python 标准库、pip 和 npm 为预置能力。对话新增包只写入 `userData/call-ai/packages/{node,python}/`，关闭时保留。npm 禁止安装脚本，包输入只接受包名和版本。更新使用专用暂存目录，失败恢复旧版本。

`run_code` 可传内联 `code`，也可用 `scriptPath` 和可选的 `args` 直接执行已有的 Python 脚本。脚本路径可相对于本次结果目录，也可使用完整绝对路径。已有脚本的内容可能变化，因此请求批准模式每次展示完整参数并单独确认。Python 可选的 `dependencies` 逐项声明导入名 `module` 和安装名 `package`，例如 `PIL` 对应 `Pillow`。内置解释器在执行脚本的同一进程中检查导入，并加载已安装额外库。缺少模块或导入失败时返回具体项，安装仍通过 `install_package` 按当前权限执行。

“运行时与额外库”下可分别展开 Node.js 或 Python 的额外库清单，查看库名与版本。勾选后点击“清理所选”，也可点击“全部清理”清空对应运行时的额外库。两种操作均需原生确认，并在对话关闭后进行。Node.js 列出直接安装的 npm 包，由 npm 更新依赖和锁文件。Python 列出 pip 发行包，按安装记录清理并保留未选发行包共用的文件。预置运行时和库保留。检查完成后，按钮旁显示绿色勾，行末显示“状态已检查”。

Skill 从含一个 SKILL.md 的 ZIP 安装，支持压缩包根目录或嵌套目录，保留说明所在目录的相对资源。最多 1000 项，压缩及解包大小各限 10MB，SKILL.md 最多 100KB。安装过程仅提取和登记，已有文件夹安装继续可用。对话可通过审批工具从本地 ZIP 或 HTTPS 链接安装。

MCP 支持 stdio 和 Streamable HTTP。可粘贴含 `mcpServers` 的 JSON，或通过“安装 npm 包”登记 Node 入口。stdio 可使用内置 `node`、`python`、`npx`，也可填写已安装服务的绝对程序路径。HTTP 入口接受 HTTPS 或本机 HTTP。npm 安装禁用包脚本；环境变量在本机保存。对话可以请求安装 npm MCP 包、添加或编辑配置。审批后登记能力，对话中通过“/”引用时连接，外部 MCP 在本轮结束后释放。

## 聊天反馈与链接

聊天会分别显示等待模型回复和正在执行工具。收到流的完成标记后即可继续本轮，无需等待网关关闭连接。模型请求失败时，聊天在本轮思考或回复下方显示提示，区分本地空闲超时、提供商或网关的 HTTP 超时和网络连接中断。请求失败日志仅记录协议、状态和响应时间，包含收到响应头、首个及末个流事件的时间。超时和连接中断会结束本轮，并在当前窗口保留任务、已收到的正文以及已完成的工具调用和结果。发送“继续”可利用这些信息接着处理。用户消息里的重试图标将原提示词带回输入框。网页、已带入的本地附件和登记的产物使用主题强调色和图标，悬停或键盘聚焦时显示完整地址。回复中的本地链接只关联当前窗口已经带入的附件或登记的产物。

## 公式、代码与正文图示

回复生成时，已完成的段落、代码块和公式在后台逐步排版，尚未定型的末块保留原文。输出继续时复用已排版的正文节点。往上阅读时保留当前位置，回到底部后恢复跟随。超长回复或排版异常时，未排版部分保留原文。公式逐个生成 MathML，再分批写入页面；单个公式无法排版时保留该式的 TeX。

聊天支持行内 LaTeX `\(...\)`、块级 `\[...\]`，也支持 Markdown 的美元分隔符。标明语言的代码围栏会高亮，点击“复制”写入整块纯文本。

框架图、流程图和原理图使用同一条 Markdown 正文中的 `svg` 围栏，按原顺序与文字、代码和 `html` 静态片段一起显示。SVG 需要 `viewBox`，允许基本形状、文字和图内箭头，点击图示下方的“导出 SVG”选择保存路径。HTML 只重建受支持的标题、段落、列表和表格。脚本、样式、输入控件、外部资源和嵌入内容均不启用。

## 结果产物

连续模型往返只产生思考时，聊天复用同一折叠条目。产生正文后，后续模型响应另起一条。工具生成的文件归入接下来的回复，可在模型继续回复前操作。

对话中指定的结果位置优先；未指定时使用设置中的默认位置，为本次窗口创建独立子目录。临时脚本始终在会话目录中，结果不能写入运行时目录。关闭窗口不删除产物。

新建文本优先用 `write_file` 或 `write_files`。批量工具一次预检并批准最多 50 项，批准卡片展示解析后的绝对路径，空内容创建 0 字节文件。桌面由系统已知目录解析，其他位置使用完整路径。写入采用主进程文件 API 与 UTF-8，遇到冲突保留既有文件并回收本批已创建文件。审批前无需启动终端探测路径。

交付回复先链接产物，再介绍内容或用法。正文里的已登记产物路径、唯一文件名和显式链接在原位置显示为可点击的链接，完整路径可悬停或聚焦查看。重复引用保留链接，定位图标只跟随首次引用。正文未提到的产物显示在同一条回复末尾。单击链接用系统默认软件打开，点击旁边的「在文件夹中显示」图标可选中文件。同名产物可通过完整路径区分。文件链接仅在生成它的窗口内有效。

`run_code` 的工作目录与 `TABDO_OUTPUT` 均指向本次结果目录。临时文件使用 `TABDO_TEMP`，桌面路径由 `TABDO_DESKTOP` 提供。`artifacts` 接收相对结果目录的路径或用户指定的完整绝对路径。主进程在执行前预检目标，成功后只登记实际存在的普通文件。工具回执包含进程输出、输出截断状态、登记文件的名称、绝对路径和字节数，以及未登记的路径。模型可以直接引用回执中的唯一文件名交付。

系统默认目录使用“文档/TabDo/Call_AI”。已有自定义路径继续使用，旧系统默认位置的产物保留在原目录。点击“一键清理”显示原生二次确认，列出当前保存的默认位置和目录数量，只删除由本工具登记的产物子目录。该目录中的其他文件、旧默认位置以及用户指定到其他位置的产物保留。活动对话存在时禁止清理或更新运行时。产物索引只保存目录路径，不保存对话正文。

## 公网网页

每次打开窗口时“网页搜索”默认关闭，两种权限模式都以发送时的开关状态为准。开启即授权本轮调用内置网页检索和抓取，免逐次批准。关闭时也停用第三方 MCP 引用。第三方 MCP 可自行调用任意服务，引用前须开启网页搜索，连接及操作仍按当前权限模式处理。通用代码执行遵循“权限与退出”所述权限。

采用网页搜索或抓取资料后，模型按内置指令在回复末尾的“参考资料来源”中列出实际使用的网页标题和可点击链接。同一网址只列一次。未采用网页资料时省略该节。

模型的提供商直连 `https://api.deepseek.com` 时，`web_search` 和 `web_fetch` 分别调用官方 Search 和 Fetch，复用当前提供商的 Bearer 密钥。Search 只请求搜索结果，返回链接、标题和摘要，Fetch 单独读取 Markdown 正文。接口响应或模型工具参数格式错误时，模型收到可用于调整后续操作的工具错误。兼容网关按通用路径处理。参见 [DeepSeek 网页搜索与抓取](https://api-docs.deepseek.com/zh-cn/guides/search/)。

通用 `web_fetch` 读取公网 HTTPS 的 HTML 与纯文本，绑定连接使用的公网 IPv4 DNS 并逐跳检查重定向。通用检索在“呼叫AI → 网页搜索”选择 Brave Search 或博查搜索，填写对应 API 密钥。两套密钥分别由 Windows 加密保存，切换服务时可继续使用已保存的密钥。启用 JSON 接口的自建 SearXNG 可通过手动引用的 MCP 接入。网页正文作为任务资料。参见 [Brave Search API](https://api-dashboard.search.brave.com/api-reference/web/search/get) 、[博查 Web Search](https://open.bocha.cn/)和 [SearXNG 搜索接口](https://docs.searxng.org/dev/search_api.html)。

DeepSeek、Brave 和博查使用代码登记的固定 HTTPS 端点。新增内置网页 API 时，在 `callAiWeb.ts` 的固定端点表登记官方地址，通过同一入口发送凭据。搜索词和待抓取地址仅作为查询参数或正文。共用入口使用系统 DNS 以兼容代理虚拟 IP，验证服务证书、拒绝重定向并限制响应大小。新增提供商的回归应覆盖虚拟 IP、拒绝重定向、凭据只发给登记端点，以及同一会话内重新开启网页搜索。
