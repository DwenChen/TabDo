# Agent 执行指南

本文面向在 TabDo 仓库执行开发任务的自动化 Agent，与根 [AGENTS.md](../AGENTS.md)共同使用。人类开发人员的环境和模块入口见 [开发指南](development.md)。

## 建立任务上下文

默认使用 context-mode MCP 进行检索、批量读取与日志分析；文件修改使用明确的编辑工具。先阅读维护流程、生成改动索引、Bug 台账及相关模块文档，再检查 Git 状态、当前分支、远端与未提交内容。保留用户和其他任务已有改动，不能通过回滚、清空目录或重建配置获得干净状态。

区分产品规范与历史证据：当前规则说明应如何实现，历史条目说明当时实际执行了什么。历史版本号、通过数量、发布授权或预览重置均不能直接用于当前任务。需要发布时依据当前用户指令确定授权范围。

## 推进与实现

先定位运行链和资源所有者，再修改最小的相关模块。数据、功能码和插件身份保持兼容；旧名称只有存在消费者时作为兼容入口保留。新增函数与实质修改函数按 JSDoc 规则写清职责、参数、返回值和主动抛错条件。

界面修改需要真实宿主入口验证；不能只挂载 Vue 组件跳过命令路由、尺寸、任务栏与会话管理。工具或插件退出立即停止前台工作，必要任务登记完整链，异步迟到不得复活页面。持久资料与宿主全局剪贴板采集不属于会话清理范围。

每轮新增或更新 `docs/history/entries/*.json`，说明原因、变化、验证、未验收项和预览状态。修复 Bug 同步 `docs/history/bugs.json` 与回归分组；生成索引由维护脚本刷新，不能手改。

## 验证与证据

按风险与受影响模块选择验证。窗口、插件及用户流程使用源码 Electron E2E，显式传入临时数据和旧数据目录；不得读取真实 `~/.tabdo`。不要为 E2E 构建或打包应用，也不要安装额外 Chromium。

通过 `pnpm test` 与 `pnpm test:e2e` 运行，保留自动归档的命令、日志、退出状态和截图。失败后保留失败证据，修正原因再执行相关检查。正文稳定后直接截图插件 WebContentsView 的可见区域，不能把宿主截图与插件截图拼接成验收证据。

测试结论必须与实际执行一致：跳过、未运行、仅有地址返回、只检查 API 标志或静态清单，都不能写成完整流程通过。明确保留设备、DPI、网络、格式及人工观感边界。

## 交付顺序

1. 检查最终差异与暂存范围，补全当轮事实记录。
2. 执行 `pnpm maintain` 与 `pnpm maintain:check`。
3. 按任务要求准备交付资源，使用固定免安装预览及同步脚本，核验逐文件数据保留结果。
4. 更新预览状态并再次运行维护校验，提交时保留 hooks。
5. 当前任务有远端授权时继续完成 push、云端构建、Release 及产物核验；没有授权时止于本地交付。

最终说明实际完成项、验证结果、预览位置和必要的未验收边界。远端任务需提供可访问的仓库、工作流或发行链接；不能把“已提交”或“已触发”描述成已发布。
